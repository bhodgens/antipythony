## Scope
1. **cranelift-object pipeline**: ap-ir → (02.05's internal cfg stage) → CLIF →
   object files via cranelift-object (no JITModule). Same lowering, same
   feedback-slot discipline (slots assigned at final lowering — for AoT the
   snapshot is compile-time static, no runtime cells needed on the no-feedback
   path: AoT binaries ship tier-0-native-equivalent code; adaptive tier-1 in
   the binary is a NON-GOAL for this leaf, document as future work).
2. **Runtime linking**: static-link ap-obj + ap-gc + ap-run interpreter +
   reachable-stdlib-only into the final binary. LTO dead-strip: only stdlib
   modules actually imported (transitively, via the importer's resolution
   graph) are embedded; the vendored_stdlib tree is compressed/embedded as
   data (or compiled-to-IR) — implementer picks, documents size + startup
   tradeoff in the leaf report.
3. **Entry point**: generated `main` that (a) initializes ap-gc (heap sizing
   per docs/gc-mmtk-swap.md §6, APX_MMTK_* env still honored), (b) installs
   root feeds (add_root_dict/add_root_module_ns/sys.modules hook — 02.05's
   root shim), (c) wraps execution in catch_unwind as a safety net (pon
   aot_entry pattern — panics become our exception-format abort, never a raw
   Rust panic print), (d) runs the module body, (e) maps exit code.
4. **CLI verb**: `antipythony build app.py -o app` in ap-cli (run verb already
   exists). Build artifacts cached under target dir; `--target` triple flag
   (musl for linux-gnu static, standard for macos — orchestrator text).
5. **Cross-compilation targets**: linux x86_64 musl static (PIE-less,
   statically linked libc) and macos aarch64 native. One of the two must be
   the leaf's primary verified target; the other compiles + smoke-runs
   (document which).
6. **Conformance-against-binary harness**: ap-conform gains an `--impl
   '<binary> run'` mode (pattern already cited by 03.02's harness flag) so
   the differential suite can run the BINARY, not the JIT.

## Non-goals
- Wasm artifact (Plan 03; the aoT object pipeline should be written so the
  wasm backend can reuse the cfg→CLIF stages, but no wasm work here).
- Adaptive tier-1 inside the shipped binary (JIT machinery stays ap-run-side;
  see Scope 1).
- Self-hosting build of stdlib .py → native ahead-of-time (all Python runs on
  the embedded interpreter at runtime; only the USER module matters for
  startup time).
- C extensions (master locked: v1 none).

## Gates
- `./app` (musl linux) AND the macos build each run: hello-world AND a classes
  corpus program — output byte-identical to CPython per the standard
  differential runner (semantic-pass bar per Amendment A-3 for Class-X text).
- Binary size: <= 15MB musl static (orchestrator §02.06 gate). Record actual
  size + the dead-strip breakdown in docs/aot-binary-gate.md.
- Conformance suite runs against the BINARY (not the JIT) for a 30-case slice:
  `ap-conform --impl '<binary>' --filter <slice>` green; forced-tier-0 JIT and
  binary outputs identical (same lowering — any divergence is a codegen bug).
- Exit codes: nonzero-exit corpus cases mapped correctly by the binary.
- Startup: binary startup (no warm compile) <= 2x the JIT run's for the same
  script (soft gate; record in the gate doc — catches accidental
  eager-everything embedding).
- `cargo test --workspace` 0 failed; no corpus regression; machine load policy
  respected (one heavy lane).
- Notices: `xtask notices --check` exit 0 with the static-link case covered.

## Review checklist (orchestrator, in-session)
- [ ] ap-ir untouched (structured-IR decision holds here too); lowering lives in
      ap-codegen-native
- [ ] AoT path shares the cfg→CLIF stages with 02.05 — no duplicated lowering
- [ ] Root feeds + heap sizing wired in the generated entry (a binary that skips
      GC init is the classic silent failure — verify with an alloc-heavy probe)
- [ ] catch_unwind present; a deliberate panic probe does not print a raw Rust
      panic backtrace
- [ ] Reachable-stdlib dead-strip actually strips: hello-world binary contains
      no lxml/sre/etc. payload (size breakdown proves it)
- [ ] musl binary is truly static (`ldd`/`file` clean of dynamic deps)
- [ ] 30-case binary conformance slice ran against the FILE, not `antipythony run`
- [ ] No test weakened; corpus monotonicity held
