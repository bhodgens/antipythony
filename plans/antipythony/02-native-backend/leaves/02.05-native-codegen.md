## Architectural fork: structured ap-ir vs pon flat-CFG — DECIDED: structured, documented
pon lowers ruff AST straight to a flat CFG IR (blocks + terminators) with
Python semantics resolved at lower time. Our ap-ir is a structured
statement/expression tree (crates/ap-ir/src/item.rs, expr.rs — "IR shape v0,
NOT a CFG" per the FnBody doc comment) and tier-0 (ap-run interp.rs) walks it.
**Decision (per orchestrator PROGRESS.md "default = structured, documented"):
we do NOT rewrite ap-ir into a flat CFG.** Instead ap-codegen-native performs a
LOCAL CFG lowering as its own first stage: structured ap-ir → internal
`cfg::Func` (basic blocks + terminators, pon-ir/ir.rs-shaped) owned entirely
inside crates/ap-codegen-native, then CLIF from that. Rationale recorded here
so the choice is not re-litigated per-task:
1. Tier-0 ap-run (14k-line interp.rs over structured ap-ir) is the correctness
   baseline and stays untouched semantically; two backends over ONE IR is the
   master contract (cross-crate rule 2).
2. pon's try/finally edge rewriting and generator transforms are exactly the
   machinery our CFG stage will implement — pon-study-lowering.md is the
   template, applied inside ap-codegen-native instead of ap-ir.
3. Plan 03 wasm shares the same internal CFG (03 orchestrator cites the same
   lowering step), so the stage amortizes.
Consequence for feedback slots: the structured tree has no per-inst slots;
slots are assigned ONLY at the final lowering stage (see Risk 5).

## Scope
1. **Internal CFG stage** (`cfg` module): structured ap-ir FnDef/Stmt/Expr →
   `cfg::Func` (blocks, terminators, locals with LocalId slots, exception
   regions as explicit edges). Adopt pon patterns with attribution:
   RaiseTerm-emit-then-redirect for raises, finally trampolines with value
   parking, PushExcInfo/PopExcInfo region discipline, generator state-machine
   transform with dense state numbering + cross-block spill rule (pon
   generator.rs pattern) so generator frames, OSR transfer, and tier-1 suspend
   share one mechanism. Verifier rule: PopExcInfo on every exit edge of a
   protected region (pin as an ap-codegen-native check, cf. ap-ir verify.rs).
2. **CLIF lowering + tier-0-baseline native codegen** (Cranelift): boxed-Value
   baseline lowering of every function (pon baseline.rs analogue). GC handling
   per Risk 1. Every Python-visible behavior calls through the ap-obj trait
   surface only (cross-crate rule 2).
3. **Feedback substrate** (`feedback` module, adapted from pon
   feedback.rs with attribution): one frozen-layout cell per feedback slot;
   EMPTY→MONO→POLY→MEGA state machine; seqlock-on-`packed` publication
   (read-check-recheck; writers CAS to IC_WRITING then Release-publish);
   no locks/alloc on the hot path. Tier-0 hooks: ap-run call/attr/global-load
   hot paths record operand type tags into cells. Slot assignment: at final
   lowering only, statically fixed per InstKind, plus a density assert pass
   (pon `debug_assert_suspend_numbering` analogue) — see Risk 5.
4. **Tier-1 typed codegen**: feedback snapshot on the enqueueing thread →
   metadata pass → maximal single-entry typed region (smi/i64 fast path first;
   float behind it) → entry guards + cold twin; values crossing region exits
   re-boxed; arithmetic guard failures side-exit to the cold twin.
5. **Background tier-up driver** (`tierup` module): one compiler thread, mpsc
   requests carrying function + IR snapshot + feedback snapshot; target
   pinned until retire; install = Release store / CAS QUEUED→TIER1; failure
   restores tier-0 or disables (no re-queue churn); shutdown joins compiler.
   `APX_SYNC_TIERUP=1` env forces synchronous compile for debugging.
   Hotness thresholds initially pon's (call 16, loop back-edge 10_000), tuned
   behind env vars, not constants.
6. **OSR on hot loops**: tier-0 emits OSR polls at loop back-edges; transfer
   via OsrTransferBuffer call (pon's OSR-by-call — no frame transplant), with
   the typed-region extension per Risk 2.
7. **Deopt**: cold-twin side-exit + deopt-thrash backoff (epoch doubling,
   pin-disabled) per pon; true deopt scoped per Risk 3.
8. **GC roots shim** (pairs ap-gc): per Risk 1 — this leaf DECIDES shadow
   stack vs return-address stackmap for native frames and implements it.
9. **Debug-build stack overflow fix** (queued PROGRESS.md item, "~93 chained
   calls"): run the interpreter on a dedicated worker thread with an
   explicitly sized stack (env `APX_MAIN_STACK_MB`, default ≥ 64; precedent:
   `AP_GEN_STACK_MB` 8MB fiber fix, commit 9ee848c) OR bump main-thread
   stack at startup — implementer picks one, documents the choice + measured
   chained-call depth before/after in PROGRESS.md. Gate: a 500-deep chained
   Python call probe passes in DEBUG builds without overflow.
10. **Tier transparency harness**: every conformance/differential runner gains
    forced-tier-0 vs adaptive modes; tier-1 is INVISIBLE except by timing —
    any observable difference is a bug.

## Risk plan (the top-5, each with its mitigation + early gate)
| # | Risk | Mitigation | Earliest probe |
|---|------|-----------|----------------|
| 1 | GC roots shim: root enumeration for native frames is entirely ours (MMTk gives the collector, not the roots). | Shadow stack first (thread-local pushed at every Value bind in eval hot paths — exact, ~10% overhead, already designed in docs/gc-mmtk-swap.md §4); pon stackmap.rs-equivalent (return-address → live-set registry + fp-chain walk, `preserve_frame_points=true`) as the tier-1 steady-state SECOND. Conservative fallback floor for OSR/non-registered frames (pon `set_conservative_scan_floor` analogue). Scrub discipline: zero dead stack slots between helper call and use. | alloc-under-recursion probe: forced GC during deep native recursion keeps every live temporary alive (no premature free, no pinning of garbage) |
| 2 | Typed-OSR is NET-NEW: pon OSRs only boxed baseline code (all-buffer, 16-slot cap); typed regions are entered only at function entry. | Phase it: land BOXED OSR first (direct pon adaptation, eligibility gate = live-set cap), ship tier-1 without typed-OSR, then add typed-OSR as an ordered sub-task: buffer gains per-slot repr tags (boxed/unboxed-i64), OSR entry unboxes guard live-ins at fixed offsets. Live sets > cap stay OSR-ineligible (document; do not silently drop). | loop-hotness probe: hot loop OSRs mid-function with correct live state, CPython-identical output |
| 3 | TRUE deopt (materialize interpreter state at an arbitrary PC) is the HIGHEST risk and has nothing in pon to adapt — the classic V8 problem space. | DEFAULT: do NOT attempt true deopt in this leaf. Keep the pon load-bearing invariant — every tier-1 function retains its full boxed baseline twin, tier-1 never elides a check the twin would redo — so cold-twin side-exit suffices. True deopt (needed only for tier-1-only code, inlined calls, elided bounds checks) is explicitly OUT OF SCOPE, filed as a follow-up design note (docs/tier1-true-deopt-design.md sketch only if time permits). | guard-failure probe: every speculation guard, when forced, exits to the cold twin and output stays CPython-identical (forced-guard fuzz over the corpus slice) |
| 4 | IC version-bump audit: a missed version bump under mutation is a CORRECTNESS bug (stale-wrong caches), not a perf one; the audit surface is every mutation path in ap-obj. | Type-version + dict-version counters on ap-obj types/instances/dicts (pon namespace-version scheme, abi.rs:530-556 analogue). MANDATORY audit table: enumerate every ap-obj mutation site (setattr, delattr, dict store/del/clear/update, class surgery — including the EnumDict backing-dict virtuals and __ap_dict_*__ routes from 02.03b, super_stack, cell stores) → map each to its bump → land as a checked-in doc (docs/ic-version-audit.md) + debug-build assertion mode (`APX_IC_AUDIT=1`) that cross-checks cache validity against a slow-path recompute on every IC hit. | adversarial probe suite: mutate-through-every-path (incl. metaclass hooks, __prepare__ namespaces, gc finalizers) after an IC warms; cached value must match slow path |
| 5 | Feedback-slot stability across lowering stages: our structured→CFG→CLIF pipeline has extra transforms pon lacks; if slots are assigned early and a transform reorders insts, tier-1 raw loads read the WRONG cell. | Assign slots ONLY in the final lowering stage (CFG→CLIF), never on the structured tree or mid-CFG. Density assert pass (every specializable site has exactly one slot; count stable under re-lowering of the same snapshot). Snapshot carries slot-count; mismatch = compile failure → disable, not wrong answer. | re-lowering determinism probe: same function lowered twice → identical slot assignment; mutation-during-compile probe: IC stores while tier-1 compiles → installed code still reads the right cells |

  rates never decrease (machine load policy: one heavy lane, CARGO_BUILD_JOBS=4).

  adaptive output byte-for-byte on every case (any observable difference is a bug).
