# Leaf 02.08-c: native lxml compat surface (unblocks T1 selector chain)

## Why
scrapy/__init__ -> scrapy.selector -> parsel.selector -> `from lxml import etree, html`.
lxml is a C extension (APX-CEXT refusal). The scrapy ENGINE does not use Selector;
only the __init__ re-export chain and spider-level parsing do. A native shim module
`lxml` in ap-run (same category as our native `re`) unblocks `import scrapy`.

## Required surface (audited 2026-10-21, parsel 1.12.1 + scrapy 2.19)
- lxml.etree: XMLParser, HTMLParser, fromstring, XMLSyntaxError, _Element,
  XPath, ErrorTypes, SubElement, tostring, Element
- lxml.html: HTMLParser, HtmlElement, fromstring, document_fromstring
- _Element protocol: .xpath(expr) (subset used by spider gate: //tag, @attr, text(),
  [contains(@class,'x')]), .tag, .attrib, .text, .tail, .getchildren() removal-safe,
  .iter(), .find/.findall, .get()
- HtmlElement: .cssselect via our cssselect bridge (cssselect is pure-python and imports OK)

## Gates
- T-GATE: `import scrapy` succeeds (post sys.path leaf)
- Differential: parse fixed HTML -> xpath results byte-equal vs CPython+real lxml
- Spider gate unchanged: file:// crawl + items.jsonl byte-compare

## Non-goals
- Full XPath 1.0; libxml2 error-message parity; schemata/validation
