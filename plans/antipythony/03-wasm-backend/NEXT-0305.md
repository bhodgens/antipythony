**Increment 1 (bd2422f1) — ap-host hardening (crates/ap-host only):**

1. `checks.rs` — `validate_module_surface(&[u8])` runs on RAW bytes BEFORE
   wasmtime compile, via wasmparser 0.263:
   - `aprt-version` custom-section stamp check (emitter's trailing custom
     section, payload = one ASCII digit). Supported: `[0]`. A module with a
     MISSING stamp (pre-03.05 emitter) or a drifted/future version is
     refused with `HostError::Abi` naming the version — old modules fail
     fast on ABI drift, never an instantiate-time unknown-import trap.

     `aprt`; unknown `aprt::*` symbols = ABI drift → refused. wasmparser
     0.263's import section yields GROUPS (`Single`/`Compact1`/`Compact2`

     shapes are unwrapped.
2. `str_reader.rs` — host-side `$str` reader for the abort_msg payload:
   kind 0 latin1 `$byte_arr`, kind 1 UTF-16 `$i16_arr`, kind 2 UTF-32
   `$i32_arr` (field layout mirrors emitter types.rs). Never panics —
   abort_msg is the unrecoverable path, so unreadable payloads render as
   `<aprt: ...>` diagnostics inside the host error. The LOCKED anyref-param
   deviation is kept (wasmtime host-func matching cannot express
   `(ref $str)`); the payload is now RENDERED (was: placeholder).
3. `options.rs` — `RunOptions` capability model: DEFAULT DENY. Args are an

   allowlist, host env NEVER inherited (no `.envs(std::env::vars())`
   anywhere in the crate). `capture_cap`, `argv0`, `measure_ttfb`.
4. `ttfb.rs` — `FirstBytePipe`: wraps the SAME `MemoryOutputPipe`
   (Arc-shared buffer — the normal drain still sees every byte) and fires a
   shared stamp on the first non-empty write. Intercept lives in the
   `p2_stream()` override (`wasmtime_wasi_io::streams::OutputStream`):
   p1 fd_write goes through the p2 adapter. GOTCHA: `cancel()` is an
   async-trait method — the manual impl needs the desugared
   `<'life0, 'async_trait>` signature (E0195 otherwise, and the lifetime

5. `lib.rs` — `run_with_engine_opts` (validation-first order), `RunResult`

## GOTCHAS for the next session (recorded, cost real time)

1. **TTFB elapsed direction**: stamp-after-start means
   `t.saturating_duration_since(start)`, never the reverse — and never
   mask a zero with `.max(1)`; it turned a 785ms truth into "1us".
2. **`FirstBytePipe` intercept path**: p1 fd_write goes through the
   `p2_stream()` adapter; intercepting only `async_stream()` (the p2
   default adapter) silently measures nothing. Override `p2_stream()`
   AND implement `wasmtime_wasi_io::streams::OutputStream` (+ its
   `Pollable::ready` and `cancel` — async-trait desugared signature).
3. **`dyn StdoutStream` is not Sync**: `WasiCtxBuilder::stdout` takes
   `impl StdoutStream`; `Box<dyn StdoutStream>` fails (Box impl needs
   T: Sync). Use a concrete enum dispatching to the two pipes.
4. **wasmtime-wasi-io types** (`OutputStream`, `StreamError`, `Pollable`,
   `bytes::Bytes`) are NOT re-exported through wasmtime_wasi 47 — depend
   on `wasmtime-wasi-io = "47"` + `bytes = "1"` + `async-trait` directly.
5. **wasmparser 0.263 import groups**: the import section reader yields
   `Imports::Single | Compact1 | Compact2` (module-name compaction) —
   iterate all three shapes or imports silently escape the allowlist.
6. **`cargo fmt -p <crate>` hits the whole crate**: I fmt-swept
   ap-codegen-wasm (NOT my file ownership) while normalizing ap-host;
   it cost one red ge_run_probe bisect before the revert. Check
   `git status` scope after EVERY fmt.
7. **`eprintln!` debug through wasm run**: the WASI stderr pipe captures
   module stderr; host-side eprintln (pre-drain) still reaches the
   console — fine for harness debugging.
