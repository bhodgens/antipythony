# Leaf 03.05 — ap-host WASI + runtime imports

## Source
plans/antipythony/03-wasm-backend/orchestrator.md §03.05. Design:
docs/03-wasm-representation-design.md §§0 (wasmtime >= 47 pin), 7 (aprt
import surface), 9 (threading diagnostic). Cross-reference:
docs/spec/06-observable-behavior.md S-06-21 (WASM artifact MUST produce
identical observable output) and docs/compat-contract.md parity rule.

## Scope
1. WASI p1 surface finalized: stdio (fd_write/fd_read on 0/1/2), exit
   codes (proc_exit → RunResult.exit_code), clock (aprt now_ns/wall_ns
   per design §7), args + env-lite (capability-scoped: explicit allowlist
   per Store, never inherit the host env wholesale).
2. aprt service imports implemented + versioned: abort_msg, now_ns,
   wall_ns; the module's aprt-version custom section checked at load,
   incompatible version → clear diagnostic (not a trap).
3. Runtime-helper import surface RESOLVED: design §4 decision — bignum/
   format/repr are NOT host imports (they are in-module prelude code);
   the orchestrator text ("bignum, format, repr" as imports) is narrowed
   accordingly — record the deviation in the leaf report and get
   orchestrator sign-off (it changes no master.md locked decision).
4. CLI shape: `ap-host run <module.wasm> [args...]` binary (the exact
   form tests/t16_hybrid and 03.02's harness flag cite; 04.04 ships the
   standalone runner — keep the interface identical), plus the Rust
   embedding API (run(bytes) → RunResult already exists; extend to
   run_file + args + env).
5. Startup: measure hello-world time-to-first-byte; log it in the leaf
   report (target <50ms, measured not asserted — orchestrator 03.05).
6. Threading: startup diagnostic when a module requests threads
   (wasmtime 47 removed wasi-threads — design §9); `threading` import in
   wasm mode → clear compile-time-style error, same treatment as
   C-extensions in v1.
