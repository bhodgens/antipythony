## Honest gaps

1. The shim `'i'` fix changes EXISTING S0 semantics: any extension written
   against the old `long`-writing shim needs `long`→`int` receiver fixes.
   S0 had exactly one consumer (spike.c, unaffected — long receivers);
   no compat window needed pre-workspace-graduation, but the divergence is
   now documented in docs/build-ext.md.
2. `PyUnicode_AsUTF8AndSize`'s new text hardcodes "argument 1" (the C API
   has no arg-position context at that seam); positional variants of the
   text are an S1 ParseTuple-refactor item.
3. build-ext module-name scan is text-level (finds `PyInit_<name>` in the
   source); a `#define`-aliased PyInit would still infer correctly only if
   spelled literally once. Acceptable for hand-written S0 extensions;
   real toolchain drivers (setuptools) are an S1 packaging story.
4. The `--emit-header` install copies ONE header; S1 surface growth may
   split headers (typeslots.h etc.) — the install story should follow.
5. S1 numbers in the feasibility note are estimates on top of the 10.02
   measured band; the PyObject_Call-back estimate (8–16 h) remains
   unmeasured and is the recommended S1 increment 1 time-box.
