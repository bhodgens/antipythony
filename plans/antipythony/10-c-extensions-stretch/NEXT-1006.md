## Measured CPython 3.14.7 dialect (the leaf's core deliverable)

- **PyLong_Export**: compact arm = `PyLong_AsLongAndOverflow` fits-int64
  — this INCLUDES INT64_MIN (value=-2^63, neg=0, nd=0). Non-compact:
  value=0, negative=1 only when negative, ndigits = 30-bit digit count
  (0→1 bump), digits = LSB-first u32 array, `_reserved` = NEW ref
  (FreeExport DECREFs; our arm: process-lifetime digit snapshots,
  FreeExport no-op — identical observable behavior). Error: zero-fill +
  TypeError "expect int, got %T" (%T = the TYPE name).
- **Two DIFFERENT compactness tests upstream** (the leaf's sharpest
  finding): Export uses AsLongAndOverflow; AsNativeBytes uses
  `_PyLong_IsCompact` = ONE 30-bit digit. Measured: -2^63 exports
  compact (E8) but takes the non-compact AsNative path (res=9); 2^30
  needs=4 (not 8).
- **The flags=4 endianness trap**: `_resolve_endianness` — UNS(4) has
  bits 2/1 clear → flags &= 1 → 0 → BIG endian. Measured: 255 into 16B
  with UNS writes `00*15 ff`.
- **AsNativeBytes fills**: compact n>8 sign-fill (ff/00) beyond the 8
  value bytes (BE: fill FIRST, value bytes REVERSED at the buffer end);
  non-compact `_PyLong_AsByteArray` 2's-complement + sign-fill; res =
  nbits/8 + 1 (sign bit cancels ceiling) with the negative-0x80..00 and
  positive-MSB edge cases. Errors: REJECT_NEGATIVE → ValueError "Cannot
  convert negative int"; n<0/NULL → SystemError
  "Objects/longobject.c:1215: bad argument to internal function"
  (line pinned on 3.14.7); non-int → TypeError "expect int, got %T".
- **PyLongWriter**: ndigits<=0 → ValueError "ndigits must be positive".
- **PyGILState_Check**: stays 1 AFTER full Release on the attaching
  thread (pin4 probe) — attached-for-good semantics.
- **Py_Version** = 0x030E07F0; Py_GetVersion prefix "3.14.7 " (suffix
  = compiler note, not pinned either side).

## Gate-found bugs (each cost a debug cycle)

1. **expect_int class-slot bug (the stale-class finding)**: the first
   cut put the API name ("PyLong_Export") in the err CLASS slot —
   `except TypeError` never matched, and ANY typed catch appeared to
   "re-raise stale errors". ~20 probe cycles to isolate; fix = class
   slot always "TypeError". Regression-pinned in ce_s1_1006_units.
2. **int_parts accepted Py_None** (Bool-kind handle with kind None) →
   export_none answered 0. Fix: CeKind::None rejected.
3. **FromNativeBytes signed-inversion**: `!(flags==-1 || flags&UNS)`
   made DEFAULTS UNSIGNED. Upstream longobject.c:1404: DEF = signed.
4. **AsNative compact threshold**: used int64-compact; upstream uses
   one-30-bit-digit (see dialect above).
5. **BE compact fill order**: value bytes must land REVERSED at the
   buffer end (cp. `*b++ = cv.b[i-1]` for i=8..1).
6. **Writer Finish lost digits**: clear-before-read in the table
   retired the Vec the caller had just written through.
7. **Method identity**: __func__ minted a NEW handle from the stored
   runtime Value (uf != f). Fix: the METHOD_PARTS side table caches the
   ORIGINAL arg handles (pointers as usize, Send).

  does not yet DRAIN it inside gcmod::edges_of — the conservation probe
  passes because the probe's C edges point at tracked ints, and the

  next integration leaf. Wiring gc_traverse_collect into gcmod's DFS is
  the S2 follow-up (the ap-gc dependency seam mirrors weakbridge).

  UnTrack/Del no-ops); real GC-New'd C structs need the 10.04 payload
  basicsize route (S2).

  scalability note, not a correctness one; per-mutex futex = S2).

  METHOD_PARTS) — bounded by construction sites, the S0 posture.

  process on S1); CPython's public 3.14 surface lacks the fn (pycore
