# Leaf 03.04 — ap-codegen-wasm generators, match, comprehensions

## Source
plans/antipythany/03-wasm-backend/orchestrator.md §03.04. Representation
contract: docs/spec/07-wasm-repr.md §7 (generator state struct — the
p2w-cited design; see docs/03-wasm-representation-design.md §6 and p2w

generators.rs (PEP-342 send/throw/close — the exact machinery issue #7

## Scope
1. Generators: FnDef.is_generator → body compiled to ONE wasm function
   with a br_table state dispatch on $generator.$state; live locals
   spilled to the $locals array at each yield; send/next/throw/close per
   S-02-21..25 (first-send-None, StopIteration value plumbing S-02-22,
   close → GeneratorExit throw-in S-02-25); yield from delegation
   (S-02-26) including return-value plumbing.
2. Generator expressions (Expr::Generator) as hidden generator functions.
3. Match: Stmt::Match lowering — Literal/Capture/Wildcard/Value/Group/
   Sequence/Mapping/Class/Or patterns + guards, in source order, bindings
   scoped per case (PEP 634 semantics as the native executor implements
   them — byte-identical is the bar, not a re-derivation).
4. Comprehensions: ListComp/SetComp/DictComp — own scope (S-02-2),
   inlined loop lowering (matching ap-run's comprehension evaluation
   order), walrus binds in the ENCLOSING scope (never comprehension
   scope — S-02-2 note).
5. for/else with iterators (S-02-17) where not already covered by 03.02;
   unpacking targets in for statements.
