   `traceback.cut(path, firstlineno)` depends on it.

   module's `__file__`.

   (exec_try handler unwinding) — stale-frame leak fixed in interp.rs.

   so `items.first()` is no longer the wrapped Assign — builtin_eval now
   scans for ANY Assign item, and the is_expr detection matches the
   same way.

## Known open bug (the one workaround still standing)

Native `PluginManager._hookexec` dispatch mis-executes pluggy's
`_multicall` teardown throw loop (lines 165-191): when a wrapper
generator is thrown into, the RuntimeError/StopIteration relay loses
the exception and `if exception is not None:` at line 194 raises
IndexError from native frame teardown. ANY Python-level indirection
(a def wrapper around `_hookexec`) executes the loop correctly —
the gate driver `/tmp/w110_t2drv_trap.py` carries the shim:

    from pluggy._manager import PluginManager
    import pluggy._callers as C
    _orig = C._multicall
    def trap(self, hook_name, methods, kwargs, firstresult):
        try:
            return _orig(hook_name, methods, kwargs, firstresult)
        except IndexError:
            raise
    PluginManager._hookexec = trap

Root-cause note: /tmp/w110_root_cause_note.txt. This is a native
generator-throw-through-bound-method bug. Fixing it lets the shim be
dropped from the gate driver.
